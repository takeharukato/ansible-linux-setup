## 概要

ノード再起動後の動作を `journalctl -b` オプションなどで, 起動後全体を通して確認する目的で, playbook の最後にノードをリブートさせるために使用するロールです。

各 `site.yml` の最後に以下のように記載することで, playbook の最後にノードをリブートさせます:

```yaml
    - role: force-reboot # 最後に実行するようにすること
      tags: force-reboot
```

`roles/force-reboot/defaults/main.yml` では `force_reboot` 変数の既定値を `false` に設定しています。`vars/all-config.yml` または `host_vars/<hostname>` の `force_reboot` 変数が `true` の場合, ノードを再起動します。

## 前提条件

- 対象ホストが inventory に登録済みであること
- 関連する共通変数が `vars/all-config.yml` または `host_vars/`配下のファイルで定義済みであること

## 実行方法

本ロールを単体で実行する場合は, 制御ホストで以下のコマンドを実行します。

```bash
ansible-playbook -i inventory/hosts site.yml --tags "force-reboot"
```

## 主要変数

| 変数名 | 意味 | 既定値 | 設定例 |
| --- | --- | --- | --- |
| force_reboot | 強制リブートの実行可否を制御します。 | false | true |
| reboot_timeout_sec | 再起動後の応答待ちタイムアウト秒数を制御します。 | 600 | 900 |

## 実行フロー

1. `load-params.yml` で OS 別パッケージ変数, 共通変数, 設定変数を読み込みます。
2. `package.yml`, `directory.yml`, `user_group.yml`, `service.yml`, `config.yml` を順に呼び出します (現行実装では補助処理枠です)。
3. `reboot-node.yml` で `force_reboot` が `true` の場合のみ `ansible.builtin.reboot` を実行します。
4. `force_reboot` が `false` の場合は, スキップ理由を `debug`文として出力します。

## 検証ポイント

実行者は以下の検証コマンドを実行し, 構文検査が成功することを確認します。

```bash
ansible-playbook -i inventory/hosts site.yml --syntax-check
```

期待結果: エラーが出力されず, syntax check が成功します。

## トラブルシューティング

実行者は, 症状ごとに以下の確認手順と対応を実施します。

| 症状 | 主な原因 | 確認コマンド | 期待結果 | 対応 |
| --- | --- | --- | --- | --- |
| ノードが再起動されない | `force_reboot` が `false` または未定義です。 | `ansible-playbook -i inventory/hosts site.yml --tags "force-reboot" -vv` | `Reboot skipped because force_reboot is not set to true` が出力されます。 | `vars/all-config.yml` または `host_vars/<hostname>` で `force_reboot: true` を設定して再実行します。 |
| 再起動待機でタイムアウトする | ホストの起動完了までに `reboot_timeout_sec` を超過しています。 | `ansible-playbook -i inventory/hosts site.yml --tags "force-reboot" -vv` | `Reboot host gracefully` タスクで timeout 関連メッセージが出力されます。 | `reboot_timeout_sec` を増やして再実行します (例: `900`)。 |
| 権限不足で再起動に失敗する | 再起動実行時の権限が不足しています。 | `ansible-playbook -i inventory/hosts site.yml --tags "force-reboot" -vv` | `permission denied` または `sudo` 関連エラーが出力されます。 | 実行ユーザの sudo 権限を確認し, 必要に応じて `become` 設定を見直して再実行します。 |
| 失敗原因を特定できない | 実行ログの確認範囲が不足しています。 | `ls -1 build*.log` と `grep -n "FAILED\|Reboot host gracefully\|Force reboot if enabled" build*.log` | 失敗タスク名とエラーメッセージが抽出されます。 | 抽出結果を基に不足変数または接続設定を修正して再実行します。 |

## 注意事項

- 本ロールは playbook の末尾で実行し, 後続タスクを配置しません。
- 本ロールはホストを再起動するため, 実行者はメンテナンス時間内で実行します。
- `force_reboot: true` を広域グループに設定する場合は, 対象ホスト範囲を事前に確認します。
